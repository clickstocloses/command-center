# HighLevel facts

Live-tested behavior of HighLevel, its API and its developer portal. Read before touching HighLevel code. Add a dated line when you learn something. Newest at the top of each section.

## Marketplace developer portal (marketplace.gohighlevel.com)

- 2026-10-23: **Command Center app** is app id `6adbaef517cfbe55659d0934`, private, target Sub-Account, install "Agency only", white-label listing. Custom page id `6adbb028b2f372a738f49bf1`. Settings live at `/app-settings/<appId>/version/<appId>/...`; client keys and the shared secret at `/app-settings/<appId>/secrets`.
- 2026-10-23: A redirect URL containing the letters `ghl` is rejected with "The redirect uri contains a Highlevel reference". So the OAuth callback route is `/api/oauth/callback`, not `/api/ghl/...`. The same filter applies to logos and websites that mention HighLevel for white-label apps.
- 2026-10-23: `http://localhost:3000/...` is accepted as a redirect URL and as a Custom Page "Testing URL". The Custom Page "Live URL" must be https.
- 2026-10-23: Custom Page placement options are "App details page" and "Left menu navigation". Left menu adds "Visible on" (sub-account, agency, or both) and a required icon from HighLevel's icon set (`i-cursor` is in it). Microphone and camera permissions are per-page switches, both off for now; turn microphone on when voice interviews ship.
- 2026-10-23: The client secret and the shared secret are shown once, in a dialog, when generated. They were copied straight into `.env.local` (`GHL_CLIENT_SECRET`, `GHL_SHARED_SECRET`). If lost, generate new ones in Secrets; the old ones stop working.
- 2026-10-23: Scopes granted to Command Center (14 as of 2026-11-04): `locations.readonly`, `locations/customValues.readonly`, `locations/customValues.write`, `locations/customFields.readonly`, `locations/customFields.write`, `users.readonly`, `calendars.readonly`, `calendars/events.readonly`, `contacts.readonly`, `conversations.readonly`, `conversations/message.readonly`, `saas/location.read`, `oauth.readonly`, `oauth.write` (added 2026-11-04 for `/oauth/locationToken`). Changing scopes means every location must reinstall. Scopes are edited under the app's Advanced Settings, then Auth (`/app-settings/<appId>/version/<appId>/advanced/auth`).
- 2026-10-23: The install link the portal shows is the plain OAuth authorize URL: `https://marketplace.gohighlevel.com/v2/oauth/chooselocation?response_type=code&redirect_uri=<callback>&client_id=<client id>&scope=<scopes joined by +>&version_id=<app id>`. The client id has the shape `<app id>-<suffix>`. A draft private app can be installed on the developer's own agency through this link; no publish step needed for that.
- 2026-10-23: Private apps are limited to 5 external agencies before HighLevel blocks new installs. All Clicks to Closes clients are sub-accounts of Tom's own agency, so this doesn't apply.

## Custom Page SSO

- 2026-11-04: **The handshake.** The Custom Page iframe posts `{ message: "REQUEST_USER_DATA" }` to `window.parent` and HighLevel answers with a `message` event whose `event.data` is `{ message: "REQUEST_USER_DATA_RESPONSE", payload: "<encrypted string>" }`. Outside HighLevel there is no parent, so the page gives up at once (`window.parent === window`) rather than waiting out the timeout. Code: `src/lib/embed/handshake.ts`.
- 2026-11-04: **The encryption.** The payload is `CryptoJS.AES.encrypt(JSON.stringify(user), sharedSecret)` in passphrase mode: base64 of `Salted__` + 8 byte salt + AES-256-CBC, key and IV from EVP_BytesToKey with MD5 and one round. `openssl enc -aes-256-cbc -md md5 -pass pass:<secret> -base64 -A` produces byte-identical output, which is how the test fixtures were made. Node's `crypto` decrypts it without `crypto-js`: `src/lib/ghl/sso.ts`. The secret is the app's Shared Secret (portal, Manage, Secrets), env `GHL_SHARED_SECRET`.
- 2026-11-04: **The payload fields.** `userId`, `companyId`, `role`, `type` (`agency` or `location`), `activeLocation` (present only when the page is opened inside a sub-account; absent in the agency view), `userName`, `email`. The app trusts only `activeLocation` for the sub-account, never anything in the URL.
- 2026-11-04: **Where the URLs live.** Portal, Command Center, Modules, Custom Pages, the page `6adbb028b2f372a738f49bf1`: "Live URL" is what sub-accounts load, "Testing URL" (`http://localhost:3000/embed`) is served to the developer's own agency. Whether HighLevel really serves the Testing URL to Tom's agency is still to be confirmed in the Part E end-to-end test.
- 2026-11-04: **Agency installs return an agency token, not a location token.** When an agency admin installs through the chooselocation page and picks sub-accounts, `POST /oauth/token` (even with `user_type=Location`) returns `userType: "Company"`, a `companyId`, no `locationId`, and `approvedLocations: [<location ids>]`. The app must call `POST /oauth/locationToken` (form body `companyId`, `locationId`, headers `Authorization: Bearer <agency token>` and `Version: 2021-07-28`) per approved location. That response has `access_token`, `expires_in`, `scope`, `locationId`, `userId`, `planId`, `appId`, `versionId` and **no refresh token**: mint a new one from the agency token when it expires. The minting endpoint needs the `oauth.write` scope. The agency token is refreshed with `grant_type=refresh_token` and `user_type=Company`. Stored in `ghl_agency_tokens`; minted installs have `token_source = 'agency'`.
- 2026-11-04: An agency install can come back with `approvedLocations` **empty** even after sub-accounts were ticked (seen when the app was already installed on them from earlier attempts). Fallback: `GET /oauth/installedLocations?companyId=&appId=&isInstalled=true&limit=&skip=` with the agency token (scope `oauth.readonly`) returns `{ locations: [{ _id, name, address, isInstalled, versionId, installedAt }], count, installToFutureLocations }`. The developer portal dashboard counts an install the moment HighLevel approves it, before our callback saves anything.
